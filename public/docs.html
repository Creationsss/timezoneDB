API Reference

Store and share Discord user timezones over a small JSON HTTP API.

Base URL

All endpoints live under /v1. The same routes are also served unprefixed (/get, /set, and so on) for backwards compatibility. Prefer the versioned paths in new code.

Authentication

/me, /set and /delete require a Discord OAuth session. Every other endpoint is public.

Send users through GET /v1/auth/discord; the callback sets a session cookie that is valid for one hour and stored in Redis. Browser clients must send requests with credentials included so the cookie travels with them.

Errors

Handler errors respond with a JSON object carrying a single message field. Malformed requests are rejected before the handler runs and return plain text instead: a missing or unparsable query string gives 400, a missing or unparsable form body gives 422, and a wrong Content-Type on /set gives 415. Unknown paths return the HTML 404 page, an unsupported method on a known path returns an empty 405, and /health returns its normal body on 503.

Error
{
  "message": "Invalid timezone"
}

Session failures return 401 with one of Missing session cookie, Missing session ID, Session not found, or Invalid user session. If Redis is unreachable the same endpoints return 500 with Database connection error.

CORS

/set and /delete answer OPTIONS preflights. Preflight responses advertise GET, POST, DELETE, OPTIONS and Content-Type, Authorization, and echo any Origin with credentials enabled.

Actual responses are stricter. Read-only requests (GET, HEAD, OPTIONS) have their Origin echoed back from any origin, writes only from Discord domains, and access-control-allow-credentials is sent only for those domains. A browser write from any other origin therefore passes preflight and is then blocked on the response.

Timezones

GET/v1/get

Returns stored timezone and username for the given user ID.

Query parameters

id required
Discord user ID.

Responds 404 with User not found when the user has no stored timezone.

200 OK
{
  "user": {
    "id": "123456789",
    "username": "username"
  },
  "timezone": "America/New_York"
}

GET/v1/list

Returns a JSON object of all stored timezones, keyed by user ID.

200 OK
{
  "123456789": {
    "username": "user1",
    "timezone": "America/New_York"
  },
  "987654321": {
    "username": "user2",
    "timezone": "Europe/London"
  }
}

GET/v1/timezones

Returns every IANA timezone name accepted by /set, sorted alphabetically, including backward-compatibility links such as America/Montreal.

Cached for 24 hours via Cache-Control: public, max-age=86400.

200 OK
[
  "Africa/Abidjan",
  "Africa/Accra",
  "America/Montreal"
]

POST/v1/set session

Stores the timezone for the authenticated user.

Body

timezone required
An IANA name from /v1/timezones, sent as application/x-www-form-urlencoded.

Responds 400 with Timezone is required when the value is blank, or Invalid timezone when it is not a known name.

200 OK
{
  "message": "Timezone saved"
}

DELETE/v1/delete session

Deletes the authenticated user's timezone entry.

200 OK
{
  "message": "Timezone deleted"
}

GET/v1/stats

Returns aggregate usage statistics.

recent_registrations counts users who registered since the start of the current calendar week (Monday), and top_timezones is capped at ten entries. total_timezones is an alias of total_users and always equals it; the distinct count is unique_timezones.

200 OK
{
  "total_users": 42,
  "total_timezones": 42,
  "timezone_distribution": {
    "America/New_York": 12,
    "Europe/London": 8
  },
  "top_timezones": [
    {
      "timezone": "America/New_York",
      "count": 12
    }
  ],
  "unique_timezones": 15,
  "top_timezone": "America/New_York",
  "recent_registrations": 3
}

Authentication

GET/v1/auth/discord

Starts the OAuth2 flow and responds 302 to Discord's authorize page.

Query parameters

redirect optional
Where to send the user after login. Carried through OAuth state and must be a relative path. Absolute URLs are rejected on the way back.
302 Found
Location: https://discord.com/oauth2/authorize
  ?client_id=...
  &redirect_uri=...
  &response_type=code
  &scope=identify

GET /v1/auth/discord/callback

Handles the OAuth2 redirect and sets the session cookie. Responds 302 to the original redirect target, or 200 with a JSON body carrying message, user and session_id when none was supplied. Authenticate with the cookie; session_id is not accepted anywhere else.

Set-Cookie
session=...; Max-Age=3600; Path=/;
  SameSite=None; Secure; HttpOnly

GET/v1/me session

Returns Discord profile info and timezone for the current session. timezone is null when the user has not stored one.

200 OK
{
  "user": {
    "id": "123456789",
    "username": "username",
    "discriminator": "0",
    "avatar": "a1b2c3"
  },
  "timezone": "America/New_York"
}

GET/v1/logout

Clears the session cookie and deletes the session from Redis.

Responds Already logged out when no session cookie was sent.

200 OK
{
  "message": "Logged out successfully"
}

Service

GET/v1/health

Reports service and dependency health. Responds 503 when either dependency is down.

200 OK
{
  "status": "healthy",
  "database": true,
  "redis": true,
  "timestamp": "2026-09-12T17:19:06.117916Z"
}
